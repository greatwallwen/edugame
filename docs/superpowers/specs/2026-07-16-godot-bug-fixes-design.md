# Godot 双游戏缺陷修复设计

## 范围

修复已复现的四项缺陷：两个游戏完成时固定上报 0 星、内部重新开始后无法再次上报完成、Ch11 接收宿主暂停命令后仍继续运行、Ch11 忽略宿主传入的 `maxLeaks`。

## 设计

1. 星级继续由播放器根据当前关卡 `starThresholds` 计算。Godot 运行时以 `-1` 表示未指定星级，桥接层发送完成消息时不写 `stars` 字段；两个游戏改为使用该默认值，不复制阈值逻辑。
2. `DGBRuntime.begin_attempt()` 重置完成上报锁，但只在已有有效会话时重新标记为 initialized。Ch11 在实际开始一局时调用，Ch12 在 `_reset_run()` 时调用。宿主 RESET 仍沿用现有重置流程。
3. Ch11 游戏根节点使用可暂停处理模式；`DGBRuntime` 与桥接节点继续使用 `PROCESS_MODE_ALWAYS`，保证树暂停后仍能收到 RESUME。
4. Ch11 新增实例值 `max_leaks`，默认取 `MAX_LEAKS`，会话初始化时读取 `config.max_leaks` 并限制为至少 1。泄漏结束判断与录制保护逻辑统一使用实例值。

## 验证

- 共享运行时测试验证缺省星级不会出现在完成消息中，并验证新一局可以第二次完成、无会话时不能激活上报。
- Ch11 集成测试验证 `maxLeaks` 注入、动态泄漏阈值、暂停处理模式和重开后的再次完成。
- Ch12 集成测试验证内部重开后的再次完成。
- 同步共享运行时后运行两个项目全部 Godot 测试、Python 测试、TypeScript 测试与类型检查，再重新导出并检查两个 Web PCK。
