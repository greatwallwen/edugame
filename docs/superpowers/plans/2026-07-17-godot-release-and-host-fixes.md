# Godot 双游戏缺陷修复实施计划

**目标：** 按审计优先级修复两个 Godot 游戏的发布、宿主、导出、统计和协议缺陷，并保持本地未提交状态。

**架构：** 用一个白名单驱动的 Node 发布工具收口导出与缓存版本；宿主侧把展示和初始化 gate 抽成可测试逻辑；游戏侧用小型纯函数修正配置相关统计。

## 任务 1：发布目录与缓存

1. 为发布工具的目录清理、PCK 哈希注入和入口 URL 同步写失败测试。
2. 实现 `export_web.mjs` 并接入根 package script。
3. 运行两个游戏导出，确认无孤儿 PCK/日志且哈希一致。

## 任务 2：结果展示

1. 写 Ch11、Ch12 与通用 Godot 结果展示测试。
2. 实现结果展示模型并更新 `ResultView`。
3. 运行 `@dgbook/game` 测试和类型检查。

## 任务 3：单次初始化

1. 写 init gate 的重复认领与重置测试。
2. iframe load 只重置，READY 经 gate 触发 INIT。
3. 复跑宿主测试。

## 任务 4：Ch12 导出过滤

1. 写两个 export preset 的排除规则测试。
2. 更新 Ch12 preset。
3. 重新导出并检查实际 PCK 文件列表。

## 任务 5：Ch11 UI 与统计

1. 写动态泄漏阈值和跨关卡 wavesCleared 失败测试。
2. 实现阈值及已清波统计。
3. 运行 Ch11 GDScript 和 Python 测试。

## 任务 6：协议防御与总回归

1. 写畸形消息、NaN、非法星级测试。
2. 收紧消息验证与结果归一化。
3. 运行 runtime 同步、两个 Godot 项目测试、`@dgbook/game`、课程嵌入测试和播放器构建。
4. 核对工作区改动，保持未提交。
