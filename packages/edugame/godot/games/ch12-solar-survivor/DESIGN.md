# 追光幸存者：第 12 章复习小游戏设计

## 1. 定位

`追光幸存者` 是面向第 12 章“太阳追踪控制系统”的 5 分钟内章节复习小游戏。

它借鉴类《吸血鬼幸存者》的自动成长、自动技能、经验升级节奏，但不强调动作难度。玩家主要体验是：

- 自动收集普通光能
- 主动追逐偏移光能带
- 光能满后触发升级
- 升级前答题
- 答对获得强升级
- 答错记系统故障
- 错题达到上限后追光系统停机

核心原则：

```text
操作低难度，答题高权重。
```

玩家不应因为走位、碰撞、弹幕或复杂操作失败。失败主要来自第 12 章知识掌握不足。

## 2. 目标章节知识

本游戏覆盖第 12 章整章知识，而不是单个知识点。

推荐覆盖模块：

| 模块 | 游戏化表达 |
| --- | --- |
| 四象限光敏传感器 | 光源方向、偏移光能带、水平/垂直误差 |
| 舵机 PWM 控制 | 20ms 周期脉冲、脉宽映射角度、追光臂动作 |
| 误差计算 | 四象限亮度差、归一化误差、追光效率 |
| Kp 比例增益 | 误差越大修正越强，提高响应速度 |
| Ki 积分增益 | 累积长期偏差，消除稳态误差 |
| Kd 微分增益 | 根据误差变化率提供阻尼，抑制抖动和超调 |
| 死区阈值 | 小误差不动作，避免舵机来回抖动 |
| 积分限幅 / 抗饱和 | 限制积分累积，防止输出饱和后继续“憋大招” |
| 输出限幅 | 限制舵机角度或控制量范围，保护机构 |
| 性能评估 | 平均误差、最大偏移、稳定度、追光效率 |

## 3. 单局时长与节奏

MVP 推荐参数：

```text
单局时长：5 分钟
升级次数：6-8 次
答题时间：10 秒
答错上限：3 次
普通光能：全屏自动收集
偏移光能：靠近后吸收
胜利条件：坚持到 5 分钟并结算
失败条件：系统故障达到 3 次
```

后续如果题库量足够，可以提供两种模式：

| 模式 | 答错上限 | 适用场景 |
| --- | ---: | --- |
| 练习模式 | 5 | 初学、课中互动 |
| 挑战模式 | 3 | 章节复习、课后测验 |

MVP 先实现挑战模式，默认 3 错停机。

## 4. 核心循环

```text
进入地图
  -> 普通光能持续生成并自动飞向玩家
  -> 太阳方向变化时出现偏移光能带
  -> 玩家移动到偏移光能带附近吸收高价值光能
  -> 光能条满
  -> 弹出答题面板
  -> 答对：选择强升级
  -> 答错：系统故障 +1，获得弱奖励或无升级
  -> 回到地图
  -> 5 分钟结算或故障满额停机
```

这个循环中，玩家移动只影响效率，不直接造成失败。答题才决定生存压力。

## 5. 资源机制

### 5.1 普通光能

普通光能是基础经验资源。

规则：

- 自动生成在地图各处
- 不需要玩家靠近
- 会全屏自动飞向玩家
- 吸收后增加光能条
- 用于保证玩家持续成长

教学含义：

```text
普通光能 = 系统正常采集到的太阳能。
```

### 5.2 偏移光能带

偏移光能带是玩家主动参与的主要来源。

规则：

- 每隔一段时间在地图一侧出现
- 代表太阳方向发生变化
- 偏移光能不会全屏自动吸收
- 玩家靠近后才会被吸收
- 吸收后提供更高光能、追光效率和结算加成
- 没追到不失败，只影响效率和升级速度

教学含义：

```text
偏移光能带 = 光源方向变化后，追光系统需要调整姿态才能捕获的能量。
```

### 5.3 稳定度

稳定度是表现控制系统状态的非致命指标。

规则：

- 初始 100
- 答错会明显降低稳定度
- 部分升级可以恢复或提高稳定度
- 稳定度不直接导致死亡
- 影响结算分数和视觉表现

视觉表现：

- 稳定度高：太阳能板动作平滑，光能轨迹清晰
- 稳定度低：光斑轻微抖动，面板有警示线，追光臂摆动更明显

## 6. 失败与惩罚

本游戏不使用传统血条。

使用：

```text
系统故障：0 / 3
```

答错 1 题：

- 系统故障 +1
- 本次升级降级或取消
- 稳定度大幅下降
- 显示错题知识点反馈
- 回到游戏继续

答错达到 3 题：

```text
追光系统停机
```

失败结算展示：

- 答错题目
- 对应知识模块
- 正确解释
- 建议复习点

注意：

- 不要用高动作惩罚，比如反弹伤害、致命敌人、复杂弹幕。
- 惩罚应主要来自答题。
- 失败原因必须清晰归因到知识点。

## 7. 升级机制

每次光能条满，进入升级答题。

流程：

1. 暂停地图
2. 显示题目，限时 10 秒
3. 玩家选择答案
4. 判断正误
5. 答对：进入强升级三选一
6. 答错：系统故障 +1，给弱奖励或无奖励
7. 返回地图

### 7.1 答对奖励

答对后出现 3 个升级选项。

升级应同时具备：

- 游戏效果明确
- 对应知识点明确
- 视觉反馈明显

示例升级：

图标可继续使用短标签 `P / I / D / PWM / DZ / LIM`，但升级面板标题和说明必须使用专业名称：`Kp / Ki / Kd`、舵机 PWM 脉宽、死区阈值、输出限幅。短标签只服务视觉识别，不替代概念讲解。

图标隐喻建议：

| 标签 | 专业概念 | 推荐图标隐喻 |
| --- | --- | --- |
| P | Kp 比例增益 | 放大器 / 增益斜坡 / 输入输出箭头 |
| I | Ki 积分增益 | 电容充电 / 蓄能罐 / 逐渐抬升的液位 |
| D | Kd 微分增益 | 阻尼电阻 / RC 微分网络 / 快速斜率被压平 |
| PWM | 舵机 PWM 脉宽 | 方波脉冲 + 舵机臂 |
| DZ | 死区阈值 | 中间空窗区 / 小误差不动作区 |
| LIM | 输出限幅 | 上下限夹轨 / 舵机角度限位 |

| 升级名 | 知识点 | 游戏效果 |
| --- | --- | --- |
| 四象限感知 | 光敏阵列 | 偏移光能带出现前给方向提示 |
| 水平误差计算 | 左右光敏差值 | 提高左右方向偏移光能吸收效率 |
| 垂直误差计算 | 上下光敏差值 | 提高上下方向偏移光能吸收效率 |
| 四象限归一化 | 误差计算 | 使用 `(右-左)/总光强`、`(上-下)/总光强`，弱光时追光效率更稳定 |
| 舵机 PWM 标定 | PWM 脉宽控制 | 将控制量映射到安全舵机角度，偏移带靠近判定范围扩大 |
| Kp 比例增益 | 比例控制 | 偏移越大追光修正越快，提高偏移光能吸收速度 |
| Ki 稳态补偿 | 积分控制 | 持续偏差会缓慢补偿，减少光斑长期偏在一侧 |
| Kd 阻尼预测 | 微分控制 | 误差变化太快时提前减缓，降低抖动并提升稳定度恢复 |
| DZ 死区阈值 | 小误差忽略 | 很小的光斑偏移不触发动作，减少无意义抖动 |
| LIM 输出限幅 | 舵机限位 | 控制输出被限制在安全范围，避免追光臂越界 |
| Anti-windup 积分限幅 | 抗积分饱和 | 输出已到限幅时停止继续累积积分，答错导致的稳定度下降减少 |

### 7.2 答错惩罚

答错后不进入强升级。

可选惩罚：

- 系统故障 +1
- 当前升级取消
- 稳定度 -25
- 偏移光能带短暂减少收益
- 下一次题目不会变难，但会从错题模块中提高出现概率

MVP 推荐：

```text
答错 = 系统故障 +1 + 稳定度 -25 + 无强升级
```

## 8. 题库结构

题库应按知识模块组织，便于结算反馈和后续自适应复习。

建议 JSON schema：

```json
{
  "id": "ch12-pid-d-role-001",
  "chapter": "ch12",
  "module": "pid",
  "knowledgePoint": "D 项作用",
  "difficulty": 2,
  "prompt": "PID 控制中 D 项主要用于什么？",
  "choices": [
    "抑制变化趋势，减少超调和抖动",
    "消除长期稳态误差",
    "提高 PWM 频率",
    "扩大 ADC 采样范围"
  ],
  "answerIndex": 0,
  "explanation": "D 项根据误差变化率进行抑制，常用于减少超调、降低振荡趋势。",
  "upgradeTags": ["damping", "stability"]
}
```

字段说明：

| 字段 | 用途 |
| --- | --- |
| `id` | 题目唯一标识 |
| `chapter` | 章节 |
| `module` | 大知识模块 |
| `knowledgePoint` | 具体知识点 |
| `difficulty` | 1-5 |
| `prompt` | 题干 |
| `choices` | 选项 |
| `answerIndex` | 正确答案索引 |
| `explanation` | 答错/结算反馈 |
| `upgradeTags` | 答对后可关联的升级池 |

## 9. 第 12 章题目方向

MVP 至少准备 20-30 题。

建议分布：

| 模块 | 数量 |
| --- | ---: |
| 四象限光敏 | 4-5 |
| 舵机 PWM | 4-5 |
| 误差计算 | 3-4 |
| PID 三项作用 | 6-8 |
| 死区 / 限幅 / 稳定性 | 5-6 |
| 性能评估 | 3-4 |

题目风格：

- 短题干
- 4 个选项
- 10 秒内能读完
- 避免长公式
- 优先问“作用、场景、判断”
- 少问纯记忆参数

## 10. 地图与视觉

MVP 地图：

- 2D 顶视角
- 浅色电路板背景
- 玩家是一个追光控制核心
- 屏幕中央或玩家身上有太阳能板图标
- 普通光能是小金点，自动飞向玩家
- 偏移光能带是地图边缘或某一方向出现的金色区域
- 稳定度低时，光斑和太阳能板轻微抖动

不要做：

- 大量怪物围攻
- 复杂碰撞伤害
- 高速弹幕
- 操作失败致死

可以做：

- 自动技能特效
- 光能吸附
- 偏移带方向提示
- 答对后的短暂清屏或光束增强
- 最后 30 秒的高亮追光阶段

## 11. 分数系统

结算不设计星级，改用“追光分”表达本局表现。

游戏内显示：

```text
追光分：0-10000
```

回传播放器时仍兼容现有 `score: 0..100`：

```text
hostScore = clamp(round(追光分 / 100), 0, 100)
```

MVP 推荐公式：

| 来源 | 分值 |
| --- | ---: |
| 完成 5 分钟基础分 | 2000 |
| 答题正确 | 每题 +500 |
| 连对奖励 | 每次连对额外 +100，最多叠到 +500 |
| 追到偏移光能带 | 每次 +300 |
| 追光效率 | 最高 +2000 |
| 结束稳定度 | 最高 +1500 |
| 系统故障 | 每次 -1200 |
| 停机失败 | 总分上限锁到 2500 |

示例：

```text
追光分 = 基础分
       + 答题正确分
       + 连对奖励
       + 偏移光能分
       + 追光效率奖励
       + 稳定度奖励
       - 系统故障惩罚
```

设计意图：

- 玩家看到的是一个明确分数，而不是星级。
- 答题正确是最高权重。
- 操作只影响效率和加分，不直接决定失败。
- 错题惩罚很高，符合“答题是主要难度”的定位。
- 停机失败也给少量分数，方便学生知道自己并非“零收获”。

推荐结算评级文案只做文字反馈，不做星级：

| 追光分 | 结算称号 |
| ---: | --- |
| 8500+ | 稳态追光专家 |
| 7000-8499 | 高效追光手 |
| 5000-6999 | 系统调参员 |
| 2500-4999 | 待复习上机 |
| 停机失败 | 追光系统停机 |

## 13. MVP 范围

第一版只做这些：

- 可移动玩家
- 5 分钟倒计时
- 普通光能全屏自动收集
- 偏移光能带靠近吸收
- 光能条和升级触发
- 答题面板
- 答错故障计数
- 3 错停机失败
- 6-8 个升级
- 20-30 道第 12 章题目
- 结算页

第一版不做：

- 复杂敌人 AI
- 真实 PID 物理仿真
- 多地图
- 装备商店
- 角色养成
- 联机
- 高动作难度

## 14. 推荐实现顺序

### 阶段 1：灰盒原型

目标：确认核心循环跑通。

任务：

- 复制 `packages/edugame/godot/template`
- 新建 `packages/edugame/godot/games/ch12-solar-survivor`
- 做玩家移动
- 做普通光能自动吸收
- 做偏移光能带
- 做升级触发
- 做答题弹窗
- 做答错停机

### 阶段 2：题库与升级

目标：让知识点和玩法绑定。

任务：

- 建第 12 章题库 JSON
- 按模块给题目打标签
- 做升级池
- 答对后按 `upgradeTags` 推荐升级
- 答错记录知识点

### 阶段 3：结算反馈

目标：让玩家知道自己哪里掌握好、哪里要复习。

任务：

- 统计正确率
- 统计错题模块
- 统计追光效率
- 计算追光分
- 生成结算称号
- 输出复习建议
- 回传 `DGB_GODOT_COMPLETE`

### 阶段 4：视觉打磨

目标：让它像游戏。

任务：

- 电路板背景
- 光能粒子
- 偏移带方向提示
- 答对升级特效
- 稳定度低的视觉抖动
- 结算动画

## 15. Godot 与播放器回传

游戏结束时通过 bridge 回传：

```gdscript
bridge.send_complete(host_score, 0, elapsed_ms, {
	"solarScore": solar_score,
	"correct": correct_count,
	"wrong": wrong_count,
	"maxCombo": max_combo,
	"trackingEfficiency": tracking_efficiency,
	"stability": stability
})
```

注意：`stats` 只能放数字。

失败也走 `DGB_GODOT_COMPLETE`，但分数较低：

```gdscript
bridge.send_complete(host_score, 0, elapsed_ms, {
	"solarScore": solar_score,
	"correct": correct_count,
	"wrong": wrong_count,
	"shutdown": 1
})
```

说明：

- `solar_score` 是游戏内追光分，建议范围 `0..10000`。
- `host_score` 是兼容播放器的 `0..100` 分数。
- `stars` 传 `0` 仅用于兼容底层 `GameResult` 类型，Godot 小游戏结算不展示星级。

## 16. 设计红线

为了保持教学友好，第一版必须遵守：

- 不做操作死亡
- 不做碰撞扣血主机制
- 不做高压弹幕
- 不做长题干
- 不把 PID 做成硬核仿真
- 不让玩家因为“没捡到普通经验”而卡成长
- 不让答错反馈只显示“错误”，必须说明知识点
- 不展示星级作为结算目标，结算只展示分数、称号和复习反馈

## 17. 一句话总结

`追光幸存者` 的体验应该是：

```text
平时自动吸光，太阳偏了就追一下；升级靠答题，答错会让系统故障，连续错题导致追光系统停机。
```

它不是动作挑战，而是把第 12 章知识点包装进一场轻松、有反馈、有成长感的 5 分钟章节复习。
